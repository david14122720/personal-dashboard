# Feature: rediseno-integral-responsivo

## Objective
Full responsive redesign of the personal-dashboard UI so the local app is a faithful replica of the Stitch "Control Deck" designs, on desktop and mobile, without breaking any existing functionality. Runs against the PRODUCTION database only, with no git operations.

## Problem
The app already speaks a "Control Deck" language (tokens in `frontend/app/globals.css`, shell in `AppShell.tsx`) but it does not match the current Stitch project `Rediseño Dashboard Personal UI/UX` (10 prototypes pulled 2026-10-11). Surfaces diverge from the designs in layout, card structure, KPI content, chips, tables and mobile chrome.

## Why
Owner order (2026-10-11): complete visual redesign, exact replica of the Stitch screens, responsive (desktop + mobile), validated with Playwright, autonomous execution, no git.

### Prototype divergences (must be resolved, not discovered later)
The 10 screens were generated separately and are NOT one coherent system:
1. **Two palettes + two icon systems**: `dashboard-desktop.html` uses the Tailwind `deck.*` palette (`#0a0e18 / #0f1422 / #151a28 / #1f273d / #38bdf8 ...`) with inline heroicon-style SVG; `productividad-desktop-v2.html`, `habitos-desktop.html` and the four mobile files use **Material Symbols** (icon names `space_dashboard`, `bolt`, `check_circle`, `account_balance_wallet`, `key`, `tune`, `code`) with slightly different colors.
2. **Divergent sidebar in `habitos-desktop.html`**: labels `Panel Principal / Rastreador de Hábitos / Tareas y Proyectos / Finanzas / Notas / Configuración`, user "Alex Vance — En línea".
3. **Divergent sidebar footer in `finanzas-desktop.html`**: "Enlace Cuántico · 99.98% · v4.8.2-prod · Latencia 12ms".
4. **Mobile bottom nav is consistent across all four mobile files**: `Deck · Finanzas · Enfoque · Hábitos · Ajustes`.
5. `productividad-desktop-v2.html` sidebar order is `Resumen, Productividad, Hábitos, Finanzas, Tokens de API, Preferencias` (same items, different order + Material Symbols).

## Decisions
- **D1 — canonical shell**: shell + IA always from `dashboard-desktop.html`; body content per surface from its own file; mobile chrome from the four consistent mobile files. `habitos-desktop` and `finanzas-desktop` sidebars are ignored.
- **D2 — IA is not invented**: the app keeps its real IA (Resumen, Finanzas, Productividad, Hábitos, Tokens de API, Preferencias), which matches `dashboard-desktop.html`. Labels that only exist in divergent prototypes (`Movimientos`, `Inicio`, `Tareas`, `Bloc de notas`, `Panel Principal`, `Notas`, `Configuración`) do NOT become routes.
- **D3 — icons inline SVG**: Material Symbols names are mapped to equivalent inline SVG paths; no icon-font dependency.
- **D4 — no git**: everything stays in the working tree on `feat/2026-10-11-categories-finance-only` (which already carries the uncommitted C4 + Playwright work). Review-workload risk accepted by owner order and reported at close.
- **D5 — Judgment Day adaptation**: per-task gate = focused vitest suite + `node node_modules/typescript/bin/tsc --noEmit` + live Playwright screenshot review at 390/768/1440. A full dual-blind Judgment Day runs once over the finished redesign, not after every single edit (per-edit dual-blind review is disproportionate and would not converge).
- **D6 — prod DB only**: `postgres://pdbuser:***@192.168.50.120:5434/pdbname`. No local database is created, initialized or migrated. A throwaway user created with `--create-user` is used for E2E and deleted at the end.

## Constraints
- Local run recipe: `frontend` static export (`pnpm build` → `frontend/out`) served by the Rust backend on `:3000` with `STATIC_DIR`, `DATABASE_URL`, `PORT`, `SESSION_TTL_HOURS`.
- Validation breakpoints: 390 (mobile), 768 (tablet), 1440 (desktop).
- Code/comments/commits in English; visible UI copy in neutral Spanish (existing i18n keys reused, new keys added only where the design needs them).
- Reduced motion respected; existing `usePrefersReducedMotion` reused.
- `npx tsc` is a decoy in this repo — always `node node_modules/typescript/bin/tsc --noEmit`.
